Start here#

MOD/XM → YM2149 · SNDH · game stream — version 0.3

A browser tool that turns ProTracker .mod and FastTracker II .xm modules into music for the Atari ST's YM2149 sound chip (one chip: three square-wave voices, one noise generator, one envelope generator, updated 50 times a second). It also loads .sndh, .ym, .ymt, maxYMiser and Arkos files, has an FT2-style pattern editor for the chip, and exports to SNDH, YM, a C game kit, maxYMiser, Arkos Tracker 3, Furnace, WAV and raw registers.

Everything runs in your browser. There is no server and nothing is uploaded.

The two tabs#

Tab What it is for
Converter Load a module, let the tool convert it automatically, listen to the original and the YM version side by side, tune the conversion (priorities, instrument roles, options) and export.
AY pattern editor Edit the song as patterns for the three YM voices, with your own instruments, digidrums and timer effects. Reached with Edit as AY patterns → (for a module, an .sndh or a .ym), New, or by loading a .ymt, .sndh, .ym, maxYMiser or Arkos file.

Ten-minute quick start#

  1. Press Demo: Omar's Bazaar (or Load MOD / XM / SNDH / YM / YMT…, or drop a file anywhere on the page).
  2. Press Space to play. Press Tab to flip between the original (played by libopenmpt) and the YM version. The difference is the conversion.
  3. If the melody gets lost, open Manual import…, give the melody channel the priority Lead, press ▶ Full preview, and listen. See Manual import.
  4. If a drum sounds thin, set the instrument's AY role to digidrum (sample) (or tick Percussion as digidrums).
  5. Choose an export: SNDH plays in any Atari ST player; YM plays in ST-Sound and similar players.
  6. To keep working on the song by hand, press Edit as AY patterns →. This works for a loaded .sndh or .ym as well: the tune is turned back into notes and instruments (see Edit an existing SNDH or YM tune).

Glossary#

Term Meaning
YM2149 / AY The sound chip of the Atari ST (pin-compatible with the General Instrument AY-3-8910). Three tone voices (A, B, C), one noise generator, one hardware envelope.
Frame One 20 ms update (50 Hz). Each frame is 14 register values (R0–R13).
Tick The editor's time step. At 125 BPM one tick is exactly one frame.
Row / speed A pattern row lasts speed ticks. BPM sets the tick length: 2.5 / BPM seconds.
Voice One of the chip's three tone channels (A, B, C). A module has more source channels than the chip has voices.
Priority A bonus added to a source channel when the converter decides which three events win the three voices in a frame.
Buzzer The chip's hardware envelope run at audible pitch: a buzzy saw/triangle bass sound. One envelope is shared by all voices.
Sync-square A trick that restarts the square wave at the start of each note so every note begins in the same phase.
Step table An instrument defined tick by tick: volume, pitch offset, noise and tone for every 20 ms.
Digidrum A short 4-bit sample played by writing a voice's volume register from a timer interrupt.
MFP The Atari ST's timer chip (MC68901). Timer A drives the Q/S/U effects, Timer D the digidrums.
SID voice / sinus-SID / sync-buzzer The three timer effects: Q, S, U.
SNDH The Atari ST music file format: a small 68000 program plus data.
YM The register-dump format of ST-Sound (YM5!, YM6!).
.ymt The YM Tracker's native song file, read and written byte-compatibly.
Mapping A .json file with the instrument roles, channel priorities and options of a conversion.

Concepts#

The YM2149 in one page#

The chip has 14 registers that you write 50 times a second (once per video frame on an Atari ST).

Registers Function
R0/R1, R2/R3, R4/R5 Tone period (12 bit) for voices A, B, C. Frequency = 2 000 000 / (16 × period).
R6 Noise period (0–31). One noise generator for all voices.
R7 Mixer: tone/noise on or off for each voice.
R8, R9, R10 Volume (0–15) for A, B, C. Bit 4 = "use the hardware envelope instead".
R11/R12 Envelope period (16 bit).
R13 Envelope shape (0–15). Writing it restarts the envelope.

Consequences that shape everything in this tool:

  • Three voices only. A module with eight channels must be reduced to three events per frame.
  • One noise generator and one envelope generator are shared by all voices, so two drums with different noise periods cannot sound at once, and a buzzer bass uses the envelope for the whole chip.
  • Volume has 16 steps of about 3 dB each. A module's 64 volume levels are mapped onto them.
  • 50 Hz resolution. Anything faster than a frame (digidrums, SID voices) needs a timer interrupt on the ST — see Digidrums and Timer effects.

How the automatic conversion works#

  1. Replay. The module is played tick-accurately in a model of the original tracker (all MOD/XM effects, envelopes, auto-vibrato, loop detection). Every 20 ms the state of each source channel is captured: instrument, pitch, loudness, sample position.
  2. Classify. For each source instrument the tool measures the sample's pitch from its waveform cycle and decides whether it is tonal (a note) or percussive (a kick, snare, hat…).
  3. Turn into AY events. A tonal channel becomes a tone period plus a level. A drum becomes a macro (a short burst of noise and falling tone) or, if you choose, a digidrum sample.
  4. Allocate. Every frame, each candidate event gets a score: its AY volume, plus the channel's priority, plus the drum bonus for percussion, plus a stickiness bonus if it was on that voice last frame. The best three win the three voices. Events that lose are dropped — or, with Arp fill, folded into a fast arpeggio on the nearest voice.
  5. Write registers. The three winners and the shared noise/envelope state become the 14 register bytes of the frame.

The result is a register dump; every export (SNDH, YM, game kit, WAV…) is built from the same dump, so they all sound the same.

The score, in detail {#concepts-score}

score = AY volume (0–15)
      + channel priority            (Off = channel left out, Low −3, Normal 0, High +3, Lead +8)
      + drum priority bonus         (only for percussion, slider "Drum priority", default +3)
      + stickiness bonus            (if this event was on that voice in the last frame, default +1.5)

Example: a Lead note at volume 7 scores 15, the same as a Normal note at full volume, and with the stickiness bonus it keeps its voice. A Lead note beats a Normal one unless the normal one is more than 8 steps louder, which on a 16-step scale means almost never. The numbers behind the five levels are listed in the Manual import chapter; the +/− buttons in the Converter's channel table set any other value.

Two ways to get to a result#

Way Use it when Result
Converter only You want a quick YM/SNDH of a tune and a few tweaks are enough. Exports are produced directly from the frame converter.
Edit as AY patterns You want to fix things by hand, make your own instruments, add drums, add timer effects, or export to maxYMiser/Arkos/Furnace. An editable pattern song (3 voices + optional drum column) that you can save as .ymt.

Edit as AY patterns uses the same priorities and roles you set in the Converter. The converter is a rendering of the module; the pattern song is an editable approximation of it, with row-level voice allocation and step-table instruments, and all editor effects available.

A loaded .sndh or .ym can be opened the same way. Its register dump has no notes in it, so the tool works them out again: it finds the tempo, the note starts and the sound of every note, and writes them as patterns whose step-table instruments reproduce what the chip did (see Edit an existing SNDH or YM tune).

Instruments in the editor#

The editor has two kinds of instrument:

  • Classic (the YM Tracker's own kind): tone and/or noise on, a volume ADSR or a volume table, an optional hardware envelope (buzzer), arpeggio and pitch tables, vibrato.
  • Step table (this tool's extension): one row per 20 ms tick with volume, pitch offset (semitones, decimals allowed), noise period and a tone on/off switch, plus loop from and a release. This is what the converter produces for module instruments, and what the presets (drums, acid bass…) use.

A step table plus the hardware-envelope option gives a gated buzzer; plus sync-square gives the punchy bass attack; with digidrums attached an instrument becomes a drum bank.

Digidrums#

A digidrum is a 4-bit sample (16 amplitude levels) played by writing a voice's volume register thousands of times a second from an MFP Timer D interrupt. While a drum plays, its voice carries the sample (tone and noise off).

  • One drum at a time. A new drum cuts the one before it.
  • Rates between 1 kHz and 24 kHz are possible; the ST can make only certain rates, so the nearest MFP rate is used (8 kHz becomes 7989 Hz).
  • A drum is at most 16 000 bytes; an instrument carries at most 63 drums.
  • Digidrums need a real timer interrupt, so they exist only in exports that carry the drum engine: SNDH, YM6, game kit, .ymt, maxYMiser. Arkos, Furnace and the register dump cannot carry them.

Timer effects: Q, S, U#

Three YM Tracker effects use the MFP Timer A to change the chip faster than 50 Hz. Their parameter xx is pitch (high nibble) and octave (low nibble): the timer runs at 20 Hz · 2^(octave + pitch/16).

Effect What the timer does
Qxx SID voice Toggles the voice volume between its value and 0 — the classic raspy "SID" sound.
Sxx sinus-SID Same, but the on half is a rectified sine — a smoother, softer wobble.
Uxx sync-buzzer Rewrites the envelope shape register at the timer rate, restarting the envelope — a harsh hard-sync buzz.

Only one timer effect and one drum can run at a time.

Module panel#

Read-only facts about the module: file name, title, type (MOD or XM) and channel count, patterns and orders, initial speed/BPM and the length of the YM version. Composer is a text field whose content is written into the SNDH COMM tag and the YM author field.

Conversion panel#

All conversion controls re-render the preview automatically: the change is applied after a quarter of a second and the conversion of a long song takes one to three seconds (the status text shows Converting… and Rendering…).

Control Range / default Effect
Level −12…+12 dB, 0 Overall loudness mapped onto the chip's 16 volume steps. Raise it if the YM version sounds quiet, lower it if many notes sit at the maximum level.
Drum priority 0…6, 3 Bonus added to percussion when voices are handed out. Higher = drums win over melody notes more often.
Voice stickiness 0…4, 1.5 Bonus for an event that stays on the voice it had in the previous frame. Higher = fewer voice jumps and clicks, but a new important note may wait.

How-to recipes#

Each recipe is self-contained. Words in bold are buttons or fields; the full description of each is in the manuals.

Load a MOD or XM#

  1. Press Load MOD / XM / SNDH / YM / YMT… at the top, or drag the file anywhere onto the page. (To try it first, press Demo: Omar's Bazaar.)
  2. The file type is detected from its contents. ProTracker .mod (M.K., 4CHN, 6CHN, 8CHN, FLT4/8, OCTA, nnCH and similar tags) and FastTracker II .xm are supported. The module is analysed and converted at once; a status text next to the buttons shows Converting… and Rendering….
  3. Press Space to play the YM version. Press Tab to switch to the original and back. If A · Original is greyed out, you opened the page from disk — see Troubleshooting.
  4. The Conversion report at the bottom lists what the converter did and any warnings.

If the file does not load, the red box under the tabs says why (e.g. "not a MOD or XM file", or a truncated file).

Import automatically, then adjust the priority#

The automatic import keeps the three most important notes every 20 ms. When it loses something you care about:

  1. Look at Source channels → 3 voices. A high Dropped percentage (red above 10 %) means that channel is being cut down.
  2. Press + next to the channel you want to protect (each press adds 1 to its priority); − for a channel that may give way. Or press Manual import… for a better view (next recipe).
  3. Listen again. The preview refreshes by itself one or two seconds after every change.
  4. Useful companions: Arp fill (folds dropped notes into a fast arpeggio so chords survive), Voice stickiness (fewer voice jumps), Drum priority (how hard drums push melody notes out), Level (overall loudness).
  5. Reset to auto goes back to the defaults.

Manual import with channel priorities#

  1. Load the module and press Manual import… in the Conversion panel.
  2. Wait for the Analysing the channels… line to be replaced by the table. Each row is one source channel with a loudness graph, how often it sounds, how many notes it plays, its median pitch and its main instruments — enough to tell the melody from the bass and the drums.
  3. Press Suggest for a first guess (busiest pitched channel = Lead, nearly silent = Low).
  4. Press ▶ in the Solo column of a channel to hear that channel alone, converted for the chip. Press it again (■) to stop. To start somewhere else in the song, click the channel's activity graph at the point you want to hear: that channel plays from there, and a white line follows the playing position. Clicking again while it plays jumps to the new point; clicking another channel's graph switches to that channel; while the Full preview is running a click on any graph jumps the full preview instead.
  5. Set each channel's Priority: Lead for the melody, High for a bass line, Normal for the rest, Low for background parts, Off for channels you do not want at all.
  6. Press ▶ Full preview (YM2149) to hear the whole result. While it plays, keep changing priorities; the new version replaces the old after a moment. ▶ Original compares with the real module.
  7. Press Done to keep the priorities for the exports on the Converter tab, or Edit as AY patterns → to continue in the editor with the same priorities.

Tips:

  • A drum channel with priority Off leaves its percussion out entirely; keep drums at Normal and use Drum priority to adjust their weight.
  • If two channels fight for the lead role, make one High and the other Normal: the difference decides who wins a contested voice.
  • The priorities are part of the mapping file — see Save and reuse a conversion.

Change how a module instrument is played#

In the Instruments → AY role table:

  1. Find the instrument (the Detected column tells you whether it was classified as tonal or as a drum; C-4 shows its measured pitch).
  2. Choose its AY role:
    • tone (written note) — if the measured pitch is wrong (a sample with no clear pitch), this plays the note as written;
    • kick / snare / hat — if a drum was classified as tonal, or the wrong drum;
    • digidrum (sample) — to play the sample itself as a 4-bit drum;
    • mute — to leave it out;
    • custom macro… — to design its sound tick by tick (see below).
  3. Use Tr. to transpose it by semitones (e.g. −12 if a bass sits too high for the chip).
  4. For a tonal instrument with a Wave column, choose saw buzzer or triangle buzzer if you want the chip's hardware-envelope bass sound, or square tone to forbid it. (The checkbox Sample waveform → buzzer applies the analysis to all instruments.)

Custom macro: choose custom macro… in AY role, press edit next to it. The Macro editor shows one row per 20 ms. Pick a Preset as a starting point (Pluck, Organ, Bass thump…), then change the Vol, Semitones (a fraction such as 0.35 makes vibrato), Noise and Tone values. Set Loop from to the step that should repeat while the note is held (−1 = play once). Use + step / − step to lengthen or shorten.

Rename instruments#

Module instrument names are often cryptic (** Omar's Bazaar **, and Qumran). Give them names you recognise:

  1. In the Converter's Instruments → AY role table, click the name field of an instrument, type the new name and press Enter (or click elsewhere). Esc cancels; an empty field goes back to the module's own name.
  2. The same names are shown — and can be edited — in the Main instruments column of the manual import dialog, so you can rename an instrument the moment you recognise it while soloing a channel.
  3. The names are used in the macro editor, saved with Save mapping, and become the names of the instruments in the pattern editor after Edit as AY patterns → (03 Bass lead; the number prefix stays so you can tell instruments apart).
  4. In the pattern editor, rename any instrument in its editor (Edit… → Name).

Renaming never changes the sound, so it does not re-render the preview.

Make drums sound right#

Two approaches exist:

  • Synthetic drums (default). Kicks, snares and hats become short noise-and-pitch macros. They are cheap and work in every export. Switch an instrument's role between kick / snare / hat to fix a wrong classification.
  • Digidrums. Tick Percussion as digidrums. Percussion samples are resampled to 4 kHz–16 kHz and played as real 4-bit samples. Choose the Drum rate and the Drum length. Individual instruments can be forced with the digidrum (sample) role.

Digidrums need a timer interrupt: they work in SNDH, YM6, the game kit and maxYMiser exports (not Arkos or Furnace). Only one plays at a time; they take voice C while they play. If drums and a melody on voice C fight, raise Drum priority or lower that channel's priority.

Save and reuse a conversion#

  • Save mapping writes <module>_mapping.json with the options, channel priorities and per-instrument roles/transposes/waveforms/macros.
  • Load mapping… restores it, also for a different module of the same kind (a warning is shown when the module differs).
  • The mapping is plain JSON and can be edited by hand; values outside the allowed ranges are clamped when it is loaded.

Continue in the pattern editor#

  1. Press Edit as AY patterns → (in the Conversion panel or in the manual import dialog).
  2. The module becomes an editable song: patterns with row-level voice allocation, one step-table instrument per module instrument, arpeggios folded into 0xy, Fxx speed changes for exact row timing, slides and vibrato translated into 1xx/2xx/4xy. If the module has percussion, a drum channel (fourth column) and a Digidrums bank instrument are added.
  3. The conversion report is kept in a collapsed Import report panel above the song bar.
  4. Press Space to start edit mode and Right Ctrl to play the song.
  5. Save with Ctrl+S as .ymt to keep the song for later.

Change an instrument in the editor#

To use a different instrument for existing notes: put the cursor on the note's instrument column and type the new two-digit instrument number. To change many notes at once, select a block and use Transpose… with only notes of instrument … to move just one instrument's notes.

To change how an instrument sounds:

  1. Click the instrument in the Instruments list.
  2. Press Edit…. Hold Play C-5 (hold) to hear it while you work.
  3. Change what you need — everything is undoable with Ctrl+Z. Changes apply everywhere the instrument is used, in the pattern playback and in all exports.
  4. Use Duplicate first if you want to keep the old version as well, then point the notes you want to change at the copy.

Create a new instrument#

From a preset (fastest). Press New below the instrument list, then Edit…, and choose a Preset: chord ornaments (a whole chord on one voice), kick/snare/hats/tom, punchy sync-square bass, acid bass.

A classic plucked lead.

  1. New, then Edit…. Keep Sound type on classic.
  2. Tone on, noise off. Tick ADSR. Set A = 0, D = 6, S = 8, R = 8 (decay and release in ticks of 20 ms, sustain is the chip level 0–15).
  3. Optional: Vibrato speed 4 and depth 3 gives a gentle wobble; Arpeggio 0 12 adds an octave flutter.
  4. Name it, write a few notes in the pattern with this instrument selected (the Instrument counter in the song bar), and play.

A buzzer bass.

  1. New, Edit…. Tick Hard envelope: use.
  2. Shape 8 (saw down) for the classic buzz, 10 for a smoother triangle sound. Env. period: leave on follow the note, divisor 1; larger divisors play lower.
  3. Untick Tone for a pure buzzer, or tick also play the tone (sync buzz) for a harsher blend.
  4. The envelope generator is shared by all voices: only one buzzer can sound at a time, and its volume cannot be scaled.

A step-table instrument (draw the sound tick by tick).

  1. New, Edit…, set Sound type to step table.
  2. Choose a macro Preset as the starting point, then draw the volume with the mouse in the bar chart (click and drag).
  3. In the table set Semitones for pitch sweeps (e.g. 24 at step 0 falling to 0 for a kick), Noise for noise bursts and Tone to switch the square wave off for noise-only steps.
  4. Loop from step repeats the tail while the note is held; Release sets the fade after a key-off; Follow note volume lets the volume column scale it.
  5. For a kick: step 0 = vol 15, semitones 24, noise 6; then vol 15→2 falling over 8 steps, pitch 14→−6. (That is the Kick preset.)

A punchy bass with sync-square. Tick Sync-square: restart the tone at each note — every note then starts at the same phase of the square wave. It is audible on real hardware, in the SNDH/game-kit exports and in the WAV preview, and is left out of YM, maxYMiser, Arkos and Furnace.

Add and use digidrums#

  1. Choose (or create) an instrument to hold the drums and press Drums….
  2. Add drums: Load WAV… (several files at once), Add starter kit, or Add synth drum…. Select a drum and adjust Rate Hz (8000 is a good start), Gain dB, Max ms, normalise, trim silence, noise shaping and fade out; press ▶ to audition. The waveform shows the 4-bit result.
  3. Use drums in the song in one of two ways:
    • Z effect: in the effect column type Z and a drum number in the parameter, e.g. Z01 = drum 1 of the cell's instrument, played on that voice. Z00 stops the drum.
    • Drum channel: tick Drum channel, then type notes in the fourth column. Z = drum 1, S = drum 2, X = drum 3 and so on; the instrument number in that column picks the bank. === stops.
  4. Remember the limits: one drum at a time (a new one cuts the old one), the drum silences its voice while it plays, at most 63 drums per instrument and 16 000 bytes per drum.
  5. Exports that carry digidrums: SNDH, YM (as YM6), game kit, maxYMiser, .ymt. Arkos, Furnace, raw registers and the register dump cannot carry them (a warning says so).

Use the timer effects Q, S and U#

  1. Write a note with sound on a voice (tone or buzzer).
  2. In the same cell (or a later row, while the note is held) type the effect, for example Q4C.
  3. The parameter is xy: y is the octave, x the pitch step inside it. The timer rate is 20 Hz · 2^(y + x/16). A higher number means a faster, higher-pitched effect. Q00 ends it; so does a new note without an effect.
  4. Q = SID voice (rough), S = sinus-SID (smooth), U = sync-buzzer (use it on an envelope instrument).
  5. Only one timer effect runs at a time; the status line warns when the rate is out of the MFP's range and clamps it.

Timer effects work in SNDH, YM6, game kit, WAV and maxYMiser exports. They need real hardware or an emulator that runs the timer.

Write a tune from scratch#

  1. Open the AY pattern editor tab and press New (or just start; the editor opens with an empty song).
  2. Set BPM (125 is one tick per frame) and Speed (6 is a common start).
  3. Press Space (Edit on), choose an Instrument, type notes with the piano keys, F1–F8 for the octave.
  4. Use the Add step to move more than one row per note; use === (Caps Lock) to release a note.
  5. Add rows of effects: 0xy arpeggio, 1xx/2xx slides, 4xy vibrato, C volume. See the Effects reference.
  6. Add patterns with New pat, Clone pat, Repeat. Set the loop point with Loop here.
  7. Save with Ctrl+S.

Edit an existing SNDH or YM tune#

An .sndh or .ym file is a recording of what the chip did, 50 times a second. It holds no notes, instruments or patterns, so the tool works them out again.

  1. Load the file (Load MOD / XM / SNDH / YM / YMT…, or drop it on the page). For an SNDH with several subtunes, choose the Subtune (and, if the length is wrong, Seconds) first.
  2. Press Edit as AY patterns → in the Loaded tune panel. In the pattern editor you can also press Load .sndh/.ym…, which takes subtune 1.
  3. The Import report above the song bar says what was found, for example YM import: 3840 frames -> 481 rows at 8 frames per row … 870 notes -> 255 step-table instruments.
  4. Press Space, then Right Ctrl to play it, and compare with the original (Converter tab, preview).
  5. Edit as for any song: change notes, replace an instrument, add drums, then save with Ctrl+S as .ymt or export.

What you get, and what to expect:

  • Tempo. The rows run at the tune's own speed (frames per row), found from where the notes start. If a tune has no regular tempo the song runs at one frame per row (speed 1): everything is still there, but patterns are long and notes are hard to read. A tune that begins a few frames before its first full row gets a short first row (an Fxx speed change on row 0 and row 1).
  • Notes and instruments. Every note start becomes a note. What the voice did until the next note (volume, pitch relative to the note, noise, tone, hardware envelope) is written as a step-table instrument named Tone, Noise, Tone+noise or Buzzer plus a number. Notes that sounded the same share an instrument, and notes that differ only in loudness share one too (the loudness goes to the volume column). Held notes loop their tail and end with ===. Arpeggios, vibrato and slides are inside the step tables, not in 0xy / 4xy / 1xx columns, because the register dump has no way to tell them apart from notes. Edit the step table to change them, or replace the instrument.
  • Tuning. Tunes that were converted from samples are often slightly off A = 440 Hz. The tune's overall offset is added to every step, so semitone values such as -0.2 or 2.8 are normal in imported instruments. Pitches are snapped to clean values when the difference is under 0.4 % (about 7 cents).
  • Digidrums of a YM5/YM6 file or an SNDH become a bank on a Drum channel (note = drum number). A drum that played on voice A or B is moved to voice C, which is where the drum channel plays; the report counts them.
  • Timer effects (SID voice, sinus-SID, sync-buzzer) become Q, S and U on the voice's note, repeated after every new note on that voice.
  • Loop. The tune's loop frame becomes the order position the song restarts at.
  • Too many sounds. There are 255 instrument slots. If a tune has more distinct sounds, the most similar ones are merged and the report says how many and how large the difference is. A note that plays the wrong instrument sounds slightly different (a volume step or a fraction of a semitone), not wrong.
  • Check by ear. The editor plays the same registers as the original to within a few percent of the frames (a few frames differ at merged instruments and where the tune does something the editor's voice model cannot, such as changing the buzzer period during a note).

Load SNDH and YM files#

  • SNDH (.sndh, .snd, also ICE!-packed): the file is run in a built-in 68000 emulator and the chip writes are captured at 50 Hz. Use Subtune to pick one, Seconds to set the length (0 = use the TIME tag). Tunes whose player never returns or waits for hardware that is not emulated report did not return.
  • YM (.ym: YM2!, YM3!, YM3b!, YM5!, YM6!, LHA-packed): read as the register dump it is. YM5/YM6 digidrums and YM6 timer effects are imported with their samples.

Effects reference#

An effect is one letter and two hex digits (the parameter) in the effect column of a pattern cell: 4 37 means vibrato, speed 3, depth 7. The effect letters are those of the YM Tracker: 0123456789ABCDEFGHKLMPRTXYQSUZ. The status line under the pattern explains the effect under the cursor.

Timing: rows, ticks and frames#

  • A row lasts speed ticks. A tick lasts 2.5 / BPM seconds.
  • At 125 BPM a tick is exactly one 50 Hz frame, which is what an Atari ST player does. At other tempos the renderer samples the tick stream at 50 Hz: below 125 BPM a tick spans more than one frame, above it some ticks fall between two frames and are not heard.
  • Effects that "run every tick" do so from the second tick of the row on (tick 1, 2 …), not on tick 0, except where noted.

How long an effect lasts#

Group Lifetime
0xy arpeggio, 1xx and 2xx slides Only on the row where they are written. Repeat them on every row for a longer arpeggio or slide.
3xx tone portamento, 4xy vibrato, 7xy tremolo, Axy volume slide, 5xy, 6xy, H global volume slide Stay active until a new note (without the effect) is played.
Rxy and E9y retrigger Until the next note.

Timer and sample effects#

These need an MFP timer interrupt, so they exist only where an engine or an emulated timer is present (SNDH, YM6, game kit, WAV, maxYMiser; not Arkos or Furnace).

Effect Name Description
Qxx SID voice The voice's volume toggles between its value and 0 at the timer rate. Parameter xy: x (high nibble) = pitch step, y (low nibble) = octave. Rate = 20 Hz × 2^(y + x/16), e.g. Q43 = 20 × 2^(3 + 4/16) ≈ 190 Hz. Q00 ends it.
Sxx Sinus-SID The on half is a rectified sine, 32 steps per period (the interrupt runs 32× the musical rate).
Uxx Sync-buzzer The envelope shape is rewritten at the timer rate, restarting it each time. Use on an instrument with a hardware envelope.
Zxx Digidrum Plays drum xx (1–63, hex) of the cell's instrument on that voice. Z00 stops the drum. A missing drum is reported as a warning.

Rates: a timer effect runs between about 48 Hz and 20 kHz (the sinus effect up to about 625 Hz, because its interrupt runs 32 times faster); anything outside is clamped to the nearest rate the MFP can make and a warning says so. The octave nibble y multiplies the base rate by two per step:

y (octave) 0 1 2 3 4 5 6 7 8
Base rate (x = 0) 20 Hz 40 Hz 80 Hz 160 Hz 320 Hz 640 Hz 1.3 kHz 2.6 kHz 5.1 kHz

The pitch step x (0–F) raises the rate within the octave by 2^(x/16), up to almost double. Low rates give slow, rhythmic pulses, high ones the metallic "buzz".

Architecture#

Overview#

The tool is a static single-page application (TypeScript, React, built with Vite). Everything — module parsing, conversion, 68000 emulation for SNDH import, audio rendering, file writing — runs in the browser. There is no server and no network traffic except loading the page itself and, for the "original" side of the A/B switch, the vendored libopenmpt worklet.

Everything revolves around one intermediate representation: the register dump — 14 bytes per 20 ms frame — plus two small "side tracks" for the things a 50 Hz dump cannot express (digidrums and timer effects).

The converter pipeline in detail#

  1. Load — loadModule detects MOD or XM by content (isMod, XM header) and parses patterns, instruments and samples.
  2. Analyse — samples.ts and pitch.ts measure each instrument's sample cycle by autocorrelation (a clear periodicity, quality ≥ 0.75, makes it tonal; otherwise a high zero-crossing rate makes it noise — snare/hat-like — and a low one a kick); waveform.ts compares the cycle's spectrum with square, pulse, saw and triangle templates.
  3. Replay — replay.ts plays the module in a tick-accurate model (all MOD and XM effects, envelopes, auto-vibrato, loop detection) and snapshots every channel's state each 20 ms. A skip predicate (channelSkipper) excludes channels set to Off or not soloed, so those channels never enter the result.
  4. Candidate events — each sounding channel becomes a candidate: a tone period plus level, or a drum macro, or a digidrum hit, according to the instrument mapping (InstMap: auto / tone / kick / snare / hat / digi / macro / mute, transpose, wave).
  5. Allocation — per frame, score = AY volume + priority + drum bonus + stickiness; the best three win the three voices. Options adjust the rules: middle layout gives bass and drums voice B, arp fill folds the losers into arpeggios.
  6. Register generation — noise period, mixer, volume (with envelope bit), envelope shape and period are merged into the 14 registers; sync-square marks bit 5 of a volume register.
  7. Side tracks — digidrum hits become trigger codes in the DrumTrack, the voice is silenced in the registers while the sample plays.

moduleToSong (src/tracker/fromModule.ts) does the same analysis but allocates voices per row and writes a pattern song with step-table instruments instead of registers, so it can be edited. It shares the priorities, roles, names, transposes and options with the frame converter.

The pattern renderer#

src/tracker/render.ts is a pure function Song → registers, a port of the YM Tracker's player: per tick it processes the row (note triggers, instruments, effects), advances ADSR / step tables / arpeggio / pitch / vibrato / tremolo state, and writes registers. Ticks run at 2.5 / BPM seconds; frames are sampled from the tick stream at 50 Hz. Digidrums (Z, drum channel) and timer effects (Q S U) are produced as side tracks and the voice's register is silenced while a drum plays. Mute/solo in the editor are honoured here, so the editor's playback is the same renderer the exports use.

The editor store#

src/tracker/editor.ts is a small observable class: song, cursor, selection, clipboard, undo stack (references to previous Song objects; only touched rows are copied, 200 levels), order list, playback state. React components subscribe with useSyncExternalStore(ed.subscribe, ed.getVersion). The editor's audio (ed.play, ed.jam) renders the song with the pure renderer and streams it through the same Preview class the converter uses.

Audio#

src/ui/audio.ts — Preview owns one Web Audio AudioContext:

  • YM side: the register dump is rendered to PCM by src/export/ymemu.ts, a register-level YM2149 emulation (tone counters, 17-bit noise LFSR, the 16 envelope shapes, the chip's non-linear volume table, the 4-bit digidrum DAC and the timer effects), and played as a looping AudioBufferSource.
  • Original side: libopenmpt in an AudioWorklet (chiptune3), vendored under public/vendor/chiptune3. It is loaded by URL at runtime because the worklet imports sibling files; it is therefore unavailable when the page is opened from file://.
  • The A/B switch changes the gain of the two branches so position is preserved.
  • The manual import dialog creates a second Preview for the solo preview of single channels, so a solo and the main preview never overlap.

SNDH import#

src/import/sndh.ts runs the tune in a built-in Motorola 68000 interpreter (m68k.ts, 4 MB RAM, I/O page at $FF8000): it loads the file (ICE!-depacked if needed) at a base address, calls the init routine for the chosen subtune, then calls the play routine at the tune's own rate (VBL or Timer A–D) and records the YM registers once per frame. The MFP model (mfp.ts) runs timer interrupts in virtual time; every YM write made inside an interrupt is logged with a timestamp, and sndhfx.ts classifies the log into digidrums and timer effects (see the table in How-to: load SNDH). The interpreter was checked against the Musashi core in psgplay.

Register dump to patterns#

src/tracker/fromRegs.ts (regsToSong) is the inverse of the renderer for .sndh / .ym input. It never invents structure that is not in the dump; every note records what the chip did, so re-rendering the song reproduces the dump.

  1. Per-frame voice state: audible, volume, envelope flag, tone, noise, period, sync bit. A voice owned by a digidrum keeps its previous state while the sample plays.
  2. Note starts: a voice becoming audible after at least two silent frames (or after one with a pitch or level change), a volume jump of 4 or more, a switch to the envelope or an envelope shape rewrite, a pitch step to a new value that holds for three frames after the old one held for two (a single-frame excursion is an arpeggio, not a note), and the sync-square bit. Digidrum hits are added for the tempo search.
  3. Tempo: the largest frames-per-row S (2…16) for which at least 97 % (then 92 %, then 85 %) of the starts lie within a tolerance of one row grid (0 frames for S ≤ 3, 1 for S = 4…5, 2 for S ≥ 6), with the phase that fits most. No fit → S = 1. Frames before the first grid frame become a short first row.
  4. Segments: a note lasts from its start row to the next start of that voice. Frames are written as steps: level, pitch relative to the note in semitones (snapped to the tune's global tuning offset plus 1, ½, ¼, 0.1 or 0.01), noise period, tone flag, plain flag. A loudness shift is moved into the volume column (velocity instruments). A periodic tail (period ≤ 32 steps) becomes the loop; a loop that ends at a row boundary gets a === there.
  5. Instruments: segments are sorted by length; a segment reuses an existing instrument if that instrument reproduces all its frames (a prefix match, so a note cut short by the next one shares the long instrument). Buzzers get the envelope shape and either the automatic period with an integer divisor (when the observed period is within 1.5 % of a multiple) or a fixed period. More than 255 instruments are reduced by repeatedly merging the pair with the lowest cost, summed over all notes.
  6. Side tracks: drum triggers go to the drum column (note = drum number, === for a stop), timer effects to Q / S / U by the first frame of each row in which the effect runs. The loop frame becomes restartPos. Patterns are 64 rows; identical patterns are shared.

Limits: 60 000 frames and 12 000 note starts (a dump that is not music, such as a sample played through the volume register, is cut there), 255 instruments, 255 patterns for .ymt.

The 68000 engine#

src/player68k/player.s (the SNDH player), drumeng.s (digidrum + timer-effect engine) and gamedrum.s (the same engine for the C game kit) are assembled with m68k-linux-gnu-as and committed as binary blobs (player.bin, gamedrum.bin) wrapped by blob.ts; npm run build:player rebuilds them. The player reads the packed stream, writes the PSG once per 50 Hz tick, and on a drum or effect event starts an MFP interrupt handler.

Build and delivery#

  • npm run build runs tsc --noEmit then vite build, producing a static folder in dist/.
  • base: './' makes every URL relative, so the folder works from any sub-path (a Nekoweb folder URL, …/index.html) and from file://.
  • The script is emitted as a classic IIFE with defer (browsers refuse module scripts and crossorigin requests on file://), the demo module is inlined as a data URL, and the documentation is a single self-contained HTML file copied from public/docs/.

Technical specifications#

All multi-byte values are big-endian unless a format says otherwise (.ymt and .aks/.fur follow their own conventions).

Time base and registers#

Item Value
PSG clock 2 000 000 Hz (Atari ST)
Frame rate 50 Hz (one frame = 20 ms = 40 000 PSG clocks)
Tone frequency 2 000 000 / (16 × period), period 1–4095
Envelope frequency 2 000 000 / (256 × period), period 1–65535
Tick (editor) 2.5 / BPM seconds; speed = ticks per row
Maximum render length 60 000 frames = 20 minutes
Volume steps 16 (R8–R10 bits 0–3); the tracker volume column (0–64) maps to the nearest step of the chip's amplitude table

Register dump (`.regs`, internal)#

14 bytes per frame, R0…R13, no header. Two conventions of this tool inside the dump:

  • R13 = 0xFF means do not write R13 this frame. A write of the same shape retriggers the envelope, so only frames that really restart the envelope write it. When no voice ever uses the envelope (volume bit 4), R13 is never written.
  • Bit 5 of R8–R10 is the sync-square flag (the chip ignores that bit). It is stripped in YM files and maxYMiser; the SNDH player and the game-kit replayer act on it.

Packed stream (SNDH and game kit)#

Delta-coded; per frame:

A  = bit 7 "B follows" | mask of R0..R6 that changed (bits 0-6)
B  = bit 7 "event bytes follow" | mask of R7..R13 that changed (bits 0-6)     [only if A bit 7]
events (only if B bit 7):
   timer effect (at most one per frame), top two bits 00:
       X = kind<<4 | voice<<2 | cont       kind 0 = stop; 1 = SID, 2 = sinus, 3 = sync
       kinds 1..3 are followed by: prescaler code, data register
       cont = 1: a drum byte follows
   digidrum trigger, top two bits != 00:
       T = (voice+1)<<6 | drum index        drum 63 = stop
then one data byte per set mask bit, in register order
  • The loop frame always starts with a full refresh, so a loop point is self-contained.
  • Streams without drums or effects never set bit 7 of B, so older players can read them.
  • The packer returns data and loopOffset (the byte offset of the loop frame).

SNDH file#

Offset Content
0, 4, 8 Three bra.w entries: init, exit, play (SNDH convention)
12 SNDH magic, then tags: TITL, COMM (composer), CONV, YEAR, ##01 (one subtune), TC50 (Timer C, 50 Hz), TIME (seconds, 16 bit), HDNS (end of tags)

player + 12 .w number of frames

Text is Latin-1 (other characters become ?). The player calls Timer C at 50 Hz, writes the PSG, and starts an MFP interrupt handler for drum or effect events. Digidrum and timer-effect engines are included in every SNDH (they are part of the blob).

YM6 digidrum trigger (ST-Sound convention): R1 high nibble = 0x40 | (voice+1)<<4, R6 bits 5–7 = MFP prescaler, R14 = MFP data register, R(8+voice) = drum number. ST-Sound effects last one frame, so timer effects are repeated every frame they run: R1/R3 high nibble = (voice+1)<<4 | type (0x00 SID, 0x80 sinus-SID, 0xC0 sync-buzzer), prescaler in R6/R8 bits 5–7, data register in R14/R15; a frame with both a drum and an effect uses slot 1 for the drum and slot 2 for the effect. The rate stored is the musical rate (the sinus effect's interrupt runs 32× faster in the engine). R13 carries the envelope shape for sync-buzzer frames.

YM6 limits: 32 drums, no stop code (approximated), drums on different voices may overlap in ST-Sound (approximated).

Importers accept YM2!, YM3!, YM3b!, YM5!, YM6!, also LHA-packed.

Digidrum table and engine#

Table read by the 68000 engine (drumtable.ts): .w count, then per drum .l PCM offset, .w length, .b MFP prescaler code, .b MFP data register; then the PCM bytes (one byte per sample, 0–15 = chip volume step).

Item Value
MFP clock 2 457 600 Hz
Prescaler dividers code 1…7 = 4, 10, 16, 50, 64, 100, 200 (code 0 = stopped)
Data register 1–255
Rate 2 457 600 / (divider × data); the nearest achievable rate is used (8 kHz → 7 989 Hz)
Timer Timer D, vector $110, IPL 6
Voice the voice named in the trigger; tone and noise off while playing
Concurrency one drum at a time; a trigger cuts the previous drum
Max rate in the editor 24 000 Hz; converter drum rates 4–16 kHz
Max size 63 drums per instrument, 16 000 bytes each
.ymt storage 4-bit packed, low nibble first

Samples are 4-bit values written to the volume register, so amplitude follows the chip's non-linear DAC levels (the waveform view in the drum editor draws exactly that).

Timer-effect engine#

Item Value
Timer Timer A, vector $134, IPL 6
Parameter xy: pitch step x, octave y; rate 20 × 2^(y + x/16) Hz; 00 = off
Range 48.2 Hz (2 457 600 / (200 × 255)) to 20 kHz; clamped, with a warning
SID voice (Q) each tick toggles the volume register between the voice's level (full level on an envelope voice) and 0
Sinus-SID (S) 64-step table (32-step rectified sine, then 32 silent steps); level (sin32[t] × vol × 17 + 128) >> 8; interrupt rate 32× the musical rate, so the musical rate is limited to about 625 Hz
Sync-buzzer (U) each tick rewrites R13 with the current shape (restarting the envelope)
Concurrency one effect at a time; the first keeps running

Game kit#

<name>.h: <N>_FRAMES, <N>_LOOP_FRAME, <N>_LOOP_OFFSET, static const unsigned char <n>_data[] (the packed stream), and with drums <N>_DRUMS and static const unsigned short <n>_drums[] (the table, word aligned).

ymplay.h (single header, plain C, 68000 target):

Call Meaning
ymplay_start(<n>_data, <N>_FRAMES, <N>_LOOP_FRAME, <N>_LOOP_OFFSET) Once, before the first step: points the replayer at the stream and clears the registers.
ymplay_step() Advance one 50 Hz frame; fills ymplay_reg[0..13]. At the end it jumps back to the loop frame by itself.
ymplay_write() Write ymplay_reg to the PSG (supervisor mode). With drums/effects: also keeps the register shadow, leaves the volume register of the voice that plays a drum or effect alone, and starts/stops them.
ymplay_reg[14] The registers of the current frame, for games that write the PSG themselves (so sound effects can steal a voice by overriding registers first).
ymdrum_init(<n>_drums) Once, supervisor mode: takes over Timer D (and Timer A for effects). Use ymdrum_init(0) when only effects are present.
ymdrum_exit() Restores the timers and the voice volume.
ymdrum_busy(), ymfx_voice(), ymplay_trig, ymplay_fxev For hand-written PSG access; see the comment at the top of ymplay.h.

The 68000 engine is embedded as unsigned short ymdrum_code[] (1188 bytes, position independent, needs RAM). Timer D and Timer A must not be used by anything else while the music plays.

`.ymt` song file#

The YM Tracker's native format, read and written byte-compatibly (little-endian).

Field Content
Header YMT1, version u8 = 1, flags u8 (bit 0 = gzip), header size u16 = 8

Troubleshooting#

Loading and playback#

Problem Cause and fix
A · Original is greyed out The original side uses libopenmpt in an AudioWorklet, which browsers refuse when the page is opened from disk (file://). Serve the folder over http(s) (any static host, python3 -m http.server, or the published site). Everything else works from disk.
No sound at all Browsers start audio only after a click. Press ▶ Play (or Space) once; check the tab is not muted.
The preview takes seconds to update The conversion runs in your browser: a quarter of a second after the last change, then 1–3 s for a long song. The status text shows Converting… / Rendering…. Changing a priority while playing is fine; the new version replaces the old one.
"not a MOD or XM file" The contents were not recognised. Packed or Impulse Tracker / S3M files are not supported. Check the file is not a renamed archive.
A .sndh says did not return The tune's init or play routine waits for hardware that is not emulated (for example a busy-wait on a timer data register). Try another subtune or a shorter Seconds value.
An .ym has the wrong length or no loop YM files carry their own loop frame; if none is stored the tune plays once. For SNDH the loop is detected; Seconds overrides the length.
The demo does not start Press Demo: Omar's Bazaar after the page has fully loaded; the demo is embedded in the page, so no network is needed.

Files and privacy#

  • Nothing is uploaded. All conversion happens in the browser; the page makes no requests except loading itself (and, over http, the vendored libopenmpt files).
  • Settings are not stored between sessions (except the documentation's light/dark choice). Use Save mapping and Save .ymt to keep your work.
  • There is no auto-save: closing the page discards the pattern editor song. The editor asks before replacing a song that has unsaved changes.
